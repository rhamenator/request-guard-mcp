# v0.1.5 public artifact qualification

This records bounded checks against the **published** experimental v0.1.5
artifacts. The server classifies inbound request metadata supplied by an MCP
client. It does not intercept traffic or enforce agent egress.

## Public binary and client checks

The extracted public Linux glibc and musl binaries each passed:

```text
python3 scripts/stdio_release_smoke.py --binary <extracted-binary> --expected-version 0.1.5
PASS packaged stdio: initialize, tools, notification, bounded errors, recovery, injection data, secret redaction
```

The glibc binary also passed `scripts/inspector_smoke.py --expected-version
0.1.5 <extracted-binary>` using MCP Inspector 2.5.0: unauthenticated HTTP
rejection, initialize, 23 advertised tools, `classify`, and `explain`.
The official Python MCP SDK 2.3.0 passed
`scripts/python_sdk_stdio_smoke.py --binary <extracted-binary>
--expected-version 0.1.5`: initialize, tool listing, `classify`, and
`explain`. Logs appeared on stderr; the stdio protocol remained on stdout.

The bounded stdio smoke checks malformed and oversized input recovery, a
prompt-like user-agent supplied as classification data, and absence of a
synthetic authentication marker from stdout/stderr. It does not prove
resistance to arbitrary prompt injection, every MCP client, or unbounded
exhaustion. Stdio uses the launching process as its trust boundary and has no
bearer authentication. The private five-platform packaged candidate and its
limitations are documented in [v0.1.5 candidate evidence](v0.1.5-stdio-candidate.md);
the exact public artifact checks above supersede its pre-tag status note.

## Public Linux adversarial loopback subset

The exact public glibc binary had SHA256
`2c68a15272619d9b2240303815f4dcf61bc283eac3d022deb3227ea17711e25f`.
On the host's loopback interface, with synthetic credentials, it passed:

```bash
python3 scripts/ci_adversarial_smoke.py --binary <extracted-public-glibc-binary>
python3 scripts/adversarial_sustained_exhaustion_probe.py --binary <extracted-public-glibc-binary>
```

The first command completed 10/10 HTTP, 22/22 custom WebSocket, 19/19
classifier parity/evasion, 128/128 malformed-envelope, 13/13 HTTP envelope,
2/2 Redis-unavailable, 4/4 slow-client/body-limit, 3/3 synthetic-secret
logging, and 3/3 connection-cap checks. A separate bounded burst shed 128/128
connections, reported zero exceptions and recovered. These are fixed corpus
cases, not an exhaustive evasion search.

The 63.43-second sustained slow-header probe ran 12 cycles. It shed 384/384
attempted connections with zero probe errors and 12/12 post-cycle ping
recoveries. Observed process RSS rose from 11,196 to 11,632 KiB (+436 KiB);
the greatest sampled request latency was 10.47 ms. Sampled host one-minute
load ranged from 1.18 to 1.72, and sampled I/O PSI `some avg10` remained
`0.00`. These are observations from one host-side run, not general memory or
throughput guarantees. The tests did not use Kali/Ubuntu VMs, healthy
Redis/PostgreSQL recovery, or a TLS collector; those remain part of the full
[adversarial release gate](../adversarial-release-gate.md).

## npm and skill state

`scripts/package_npm.py` assembled `request-guard-mcp@0.1.5` from these
exact public archives. `npm pack` contained the GPL license, launcher,
README, and five expected binaries, with no runtime npm dependencies. Its
tarball SHA256 was
`24d9354ada9fd2de566da3577176caf979c5755d05ac582f9dd410217389d044`.
A clean local tarball installation passed Inspector 2.5.0 over HTTP and the
bounded stdio smoke. As checked on 2026-10-21 at 11:06 UTC,
`npm view request-guard-mcp@0.1.5 version` returned E404 and `npm whoami`
returned E401. Publication awaited owner CLI authentication. Recheck the
registry before following npm 0.1.5 instructions; a local tarball test does
not establish that the registry package is live.

The companion Agensi skill ZIP is prepared separately and kept off GitHub.
Its instructions explain the separate server installation, local stdio trust,
and the conditional npm availability. The owner controls the marketplace
listing.

This is evidence for the experimental release, not completion of the
[stable v1.0 gate](https://github.com/rhamenator/request-guard-mcp/issues/125).
