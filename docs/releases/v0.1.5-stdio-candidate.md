# v0.1.5 stdio candidate evidence

This is a historical pre-tag record. The [public artifact qualification](v0.1.5-public-qualification.md)
records the completed exact-tag checks and supersedes pending-publication
statements below.

This is development-source evidence, not a published installer qualification.
The public v0.1.4 release and its Agensi skill remain unchanged.

The candidate adds `request-guard-mcp --stdio` for process-local MCP clients.
It handles one newline-delimited JSON-RPC message at a time, writes protocol
responses only to stdout, and writes diagnostics to stderr. No TCP listener
starts. The child process pipes and local user permissions are the trust
boundary; HTTP bearer tokens and browser Origin validation do not apply.

## Checks on 2026-10-21

- `cargo test --locked`: full Rust suite passed.
- `cargo clippy --locked --all-targets --all-features -- -D warnings`: passed.
- `cargo test --locked --test stdio_transport`: actual binary stdout framing,
  default no-token startup, and PostgreSQL configuration rejection passed.
- The optional `scripts/python_sdk_stdio_smoke.py` passed against the built
  candidate using official Python MCP SDK 2.3.0: `initialize` negotiated
  2025-06-18, `tools/list` included `classify` and `explain`, `classify`
  blocked a synthetic GPTBot request, and `explain` returned contributing
  factors. It ran in an isolated loopback network namespace with no optional
  backend.
- A process probe confirmed one JSON-RPC stdout line for one ping and no
  stdout data on a rejected PostgreSQL configuration. A closed stdout with
  stdin left open caused exit code 1 promptly. `strace -f -e bind,listen` of
  the SDK session recorded no bind/listen syscall.
- Codex review identified HTTP-only Origin and cache-scope-key validation in
  stdio startup. The candidate now clears those unused settings and accepts
  invalid values there while retaining their validation for network mode;
  focused unit and built-binary probes passed.
- Private release workflow `39547541009` passed all five native target builds
  at source `c6ecd75` (Linux glibc, Linux musl, Windows x64, macOS Intel and
  Apple Silicon). Its packaged `scripts/stdio_release_smoke.py` step passed on
  each target, covering initialize, tool calls, notification, oversized and
  malformed input, and recovery. No public release was created. Downloaded
  archives and all five SHA256 sidecars verified. A Codex review of the new
  packaged smoke and workflow found no actionable regression.
- A dependency-free npm RC package assembled from those same five verified
  private archives installed into a clean offline npm prefix. The installed
  command passed `scripts/stdio_release_smoke.py` via its Node launcher:
  initialize, `tools/list`, `classify`, `explain`, notification, bounded errors,
  and recovery. This verifies the candidate installer locally; no RC was
  published to npm.
- An expanded packaged smoke set `MCP__AUTH__ENABLED=true` and a synthetic
  `AUTH_TOKENS` value to exercise stdio's process-local trust path. A prompt-like
  user-agent produced a normal `classify` result with the expected response
  shape after malformed-input recovery. On the private Linux glibc and musl
  binaries and clean-installed npm launcher, the synthetic token marker did
  not appear in captured stdout or stderr. This bounded check does not prove
  resistance to arbitrary prompt injection or every log leak. Private workflow
  `39570707881` ran this expanded packaged smoke successfully on all five
  targets at source `757768f`, without creating a public release. All five
  downloaded archive SHA256 sidecars verified.

## Limits before release

The candidate has no stdio session resumption, concurrency, or request
cancellation. It processes messages sequentially; tool timeouts still apply.
Automatic `.env` discovery is disabled in stdio mode; explicit environment
variables and `CONFIG_FILE` remain available. PostgreSQL is rejected because
its per-caller rows do not expire and the stdio caller scope is unique per
launch. Redis uses its configured TTL. Fresh exact-head packaged and npm
client checks remain required before v0.1.5 publication. Independent Claude
Code and Codex source reviews found no unresolved finding. SSE GET remains
unimplemented.
