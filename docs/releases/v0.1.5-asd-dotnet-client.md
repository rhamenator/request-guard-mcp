# AI Scraping Defense .NET adapter against public v0.1.5

On 2026-10-21, the AI Scraping Defense IIS repository's `McpModelAdapter` was exercised on the Linux host against the exact public Request Guard MCP v0.1.5 Linux x64 binary over authenticated loopback WebSocket. The Request Guard binary SHA256 was `2c68a15272619d9b2240303815f4dcf61bc283eac3d022deb3227ea17711e25f`. The .NET source checkout was at `177ad62d747da3eb5d2bc7f171956d2aa04cafaa`; `AiScrapingDefense.EscalationEngine/Services/McpModelAdapter.cs` had no local modifications and SHA256 `c7fd0d13b7624b5ca640fdb1158ff7efe8b6ec3bb526eb2ed6086595ffb77228`. The checkout had unrelated uncommitted work, so this is a source-file and live-code-path observation rather than a packaged release qualification.

A temporary .NET 10 console project referenced `AiScrapingDefense.EscalationEngine.csproj`, configured `McpModelAdapterOptions` with `mcp://primary/classify`, the authenticated `ws://127.0.0.1:<ephemeral>/mcp` endpoint and a synthetic token, then called `AssessAsync()` with `ThreatAssessmentContext("192.0.2.42", "GET", "/robots.txt", "", "GPTBot/1.0", [], 1, 0, 0)`. It returned `MCP_BLOCK`, `IsBot=true`, with `ua_ai_bot`, `ua_non_browser`, `header_missing_accept`, and `header_missing_accept_language`. The repository's focused `McpModelAdapterTests` passed 2/2 with `dotnet test RedisBlocklistMiddlewareApp.Tests/RedisBlocklistMiddlewareApp.Tests.csproj --no-restore --filter FullyQualifiedName~McpModelAdapterTests`.

The first direct temporary apphost invocation timed out even for the server's `/health`; OpenSnitch was blocking that executable. Running the same compiled assembly as `dotnet Probe.dll` through the host's existing exact-path allow rule returned the health response, connected with WebSocket subprotocol `mcp`, and passed the classify call. The initial timeout is a host firewall test artifact, not a confirmed Request Guard or adapter defect. This test did not run Windows IIS, an installer, a full AI Scraping Defense request pipeline, or a v1.0 candidate. Keep those as separate release gates.
