# AI Scraping Defense Rust client against public v0.1.5

On 2026-10-21, the Rust AI Scraping Defense `cloud-proxy` service at commit `ea5b73df27f31e25c0ddf1e5ba84238dd640d418` called `classify` on the exact public Request Guard MCP v0.1.5 Linux x64 binary over an authenticated loopback WebSocket. The public binary SHA256 was `2c68a15272619d9b2240303815f4dcf61bc283eac3d022deb3227ea17711e25f`; the locally built Rust `cloud-proxy` binary SHA256 was `f0ef70fbe7c2ad675f78afaa464d9cb51cddad8dbfa0d29c1ef8111948b884a1`.

The Rust service used `MODEL_URI=mcp://primary/classify` and its configured `MCP_SERVER_PRIMARY_*` WebSocket connection. Its `/api/chat` endpoint received only synthetic request metadata: TEST-NET address `192.0.2.42`, `GPTBot/1.0`, `/robots.txt`, and `GET`. The observed verdict and signals are consistent with the request fields reaching `classify`; this probe does not capture the MCP wire arguments. Request Guard returned `block`, score `0.918181818181818`, and `ua_ai_bot` plus `ua_non_browser` signals. This differs from the earlier Python generic adapter's unsafe bare-URI nesting behavior, which was fixed separately in [PR #1848](https://github.com/rhamenator/ai-scraping-defense/pull/1848).

To reproduce with separately obtained binaries, build the Rust service with `cargo build -p cloud-proxy --locked`, verify the published Request Guard archive against its SHA256 sidecar, then run:

```sh
python3 scripts/probe_asd_rust_client.py /path/to/request-guard-mcp /path/to/cloud-proxy \
  --guard-sha256 2c68a15272619d9b2240303815f4dcf61bc283eac3d022deb3227ea17711e25f
```

The stdlib probe starts both services with fresh random authentication values, waits for HTTP health responses, sends one authenticated request, checks the public binary hash, verdict, score, and signals, then terminates both processes. Two consecutive health-gated local runs passed; these observations are reported here and are not a CI result. An earlier TCP-listener-only run returned HTTP 502; the health-gated reruns passed, which is consistent with a service readiness race but does not establish its cause. The test does not cover production traffic, other tools, the Rust defense's full pipeline, deployment authentication, or a v1.0 candidate. The cloud-proxy test listener can bind beyond loopback; run this probe only in an isolated test environment.
