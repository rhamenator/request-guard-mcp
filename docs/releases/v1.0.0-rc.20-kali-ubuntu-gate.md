# Private rc.20 cross-VM and PostgreSQL TLS gate

On 2026-10-23 UTC, Kali `copperfin-kali-full` exercised the exact **private,
unpublished** v1.0.0-rc.20 Linux x64 glibc archive on Ubuntu
`copperfin-ubuntu26-deb`. A separate disposable Alpine container exercised
the matching private musl archive's PostgreSQL TLS trust behavior. This is a
bounded candidate replay, not approval to publish stable v1.0.

The PostgreSQL test created disposable database `request_guard_rc20_lab`
under peer authentication, stopped/restarted the existing PostgreSQL 18
cluster, verified it online afterward, and removed the test database. The
`copperfin` database role already existed and was left intact. Disposable
Redis ran without persistence and was stopped. The MCP processes and
temporary copied files, scripts and synthetic secrets were removed.

The core MCP log was nonempty (10,841 bytes). Exact-string checks found no
synthetic bearer, HMAC or seeded Redis indicator in the scoped core,
PostgreSQL and Redis **MCP logs**. Encoded or truncated forms were not
searched, and backend logs were not searched. Both lab guests were shut
down and verified off; the preexisting Copperfin Windows guest was left
untouched. Host I/O PSI `full avg10` was 0.00 before boot and 0.04 after
the probes; it briefly reached 1.29 during staggered startup. These point
samples do not characterize pressure throughout the run. No firewall or
host trust-store change was made.

## PostgreSQL TLS trust and limits

`scripts/smoke_alpine_postgres_tls.py` ran the exact extracted private musl
binary in Alpine 3.24.2 base image
`sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`.
It passed explicit trusted CA, untrusted CA rejection, hostname mismatch,
unmodified OS-store rejection, and OS-store trust after installing a test
CA **inside the disposable container**, plus the probe's bounded private-log
check. Test PostgreSQL and MCP used container loopback. Alpine packages
were resolved live; their exact package versions were not recorded. The
test container was removed, and Docker was returned to its initially
inactive service state.

The cross-VM checks exercised glibc; PostgreSQL TLS trust was exercised
on musl. This does not prove glibc or other-platform TLS parity,
production TLS termination, remote database failover, Redis TLS,
distributed ingress fairness, scanner capture counts, all-client
compatibility, or a 256-client deployment. No public v1 tag, release,
GHCR image, npm package or Agensi ZIP was created. Complete adversarial
LLM review, owner approval and approved-tag public artifact verification
remain in [issue #125](https://github.com/rhamenator/request-guard-mcp/issues/125).
