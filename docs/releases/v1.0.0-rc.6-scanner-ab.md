# Private v1.0.0-rc.6 Nmap A/B and HTTP coverage

On 2026-10-22, issue #174's follow-up used the same authorized Kali
`192.168.122.74` and Ubuntu `192.168.122.73:18086` guests in one boot.
Ubuntu sequentially ran the checksum-verified **public v0.1.5** Linux x64
glibc binary (SHA256
`2c68a15272619d9b2240303815f4dcf61bc283eac3d022deb3227ea17711e25f`)
and the checksum-verified **private, unmerged v1.0.0-rc.6** binary from
draft PR #149 commit `aa631dae14346822b1a9dc94fb77395be4376015`
(SHA256 `91d7355d0602974552668d15be85dbe307888e88dca21e4a2d617e1bc6b1f707`).
Both were restarted sequentially as separate systemd units with the same
synthetic bearer, port, 4,096-byte request cap, two-second header/body
deadlines and 32 connection slots. Nmap was 7.99. The v0.1.5 build has
Hyper's HTTP/1 header timer but no transport-neutral first-request deadline.
Each scan had its own immediate-write tcpdump capture; the operator read
equal captured/received totals and zero kernel drops at stop. These
operator-read stop summaries are recorded in the table, not in the pcaps;
they cannot prove traffic outside each capture window. The committed
`scripts/verify_scanner_capture.py` passed per-stream segment-boundary and
zero-retransmission checks on the observed capture only. Raw pcaps are
gitignored under `dist/v1.0.0-rc.6-scanner/ab/`, outside Git and release
assets.

The same-command A/B narrows the 30-to-1 difference. In the public capture,
TCP stream 1 SYN is frame 5 and Nmap's four-byte payload is frame 8,
6.003 seconds after SYN. In the rc.6 capture, stream 1 SYN is frame 5 and
the server's payload-free FIN is frame 8, 2.252 seconds after SYN; Nmap had
sent no payload on that connection. The candidate's
[pre-request protocol detection bound from PR #160](https://github.com/rhamenator/request-guard-mcp/pull/160)
(commit `6dc433d`, an ancestor of `aa631dae`) closes a connection without a
first request after the configured two-second header timeout plus 250 ms.
The timing is **consistent with** that intentional slot-retention defense;
we did not build a single-change control with PR #160 removed, and other
changes also separate v0.1.5 from rc.6. The rc.6 capture next shows one
`JDWP-Handshake` probe on later TCP stream 2 and HTTP 400; Nmap output labels
the port
`tcpwrapped` and stops before its HTTP scripts. This does not establish
which Nmap-internal decision produced that label. With these two-second
limits and the approximately six-second wait observed in the public capture,
the original `-sV`
command supplies no HTTP coverage for this candidate. Other timeout settings
or scanner versions could differ.

For explicit HTTP coverage, the second candidate scan omitted `-sV`, forced
the two NSE scripts with `+`, and targeted the protected path:

```bash
timeout 70s nmap -Pn -sT -p 18086 \
  --script +http-methods,+http-headers \
  --script-args 'http.host=192.168.122.73,http-headers.path=/mcp,http-methods.url-path=/mcp' \
  --max-retries 1 --host-timeout 60s 192.168.122.73
```

Separately from the verifier, the operator used
`tshark -r FILE -Y 'http.request' -T fields -e http.request.method -e http.request.uri`
and `tshark -r FILE -Y 'http.response' -T fields -e http.response.code`.
TShark decoded seven `/mcp` requests across HEAD, OPTIONS, GET and POST,
and eight HTTP 401 responses. The eighth client payload was Nmap's
intentionally invalid method `RBTI /mcp`, which TShark did not decode as an
HTTP request. The verifier counted eight wire messages in eight streams;
TShark separately decoded eight HTTP responses. The verifier found zero
retransmissions; tcpdump reported zero kernel drops.
The forced `/` scan similarly had seven decoded HTTP requests plus a random
invalid-method probe (`LXLZ /`), with eight HTTP 404 responses. The public
v0.1.5 `-sV` scan's 26 responses include replies to non-HTTP service probes,
which explains why only three requests decoded as HTTP. An authenticated
JSON-RPC `ping` still returned HTTP 200 with a valid result from the running
candidate service after the scans. No defect was observed in these bounded
unauthenticated pre-auth responses. The method/path/status fields and
post-scan `ping` are operator-read from local capture and guest output;
they are not independently verifiable from this committed document.

These scans were deliberately unauthenticated and primarily exercised the
pre-auth path. Forced scripts bypassed service detection: they show that
Nmap could send requests when directed, not that it discovered HTTP on its
own. One capture per A/B condition was taken in this follow-up; the earlier
rc.6 standard-command scan repeated the one-message observation, but timing
variance remains possible. The forced scripts do not establish tool
correctness, authenticated authorization boundaries, TLS/proxy behavior,
full scanner coverage, HTTP/2 or post-first-request lifetime behavior, or
final published v1.0 artifact behavior. The private rc.6 build remains
unmerged. Issue #125 still requires exact final-candidate replay,
independent adversarial review and owner approval. The lab server, temporary
bearer and both guests were stopped; both guests were verified off.
