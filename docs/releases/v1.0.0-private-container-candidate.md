# Private v1 container candidate on native runners

On 2026-10-22 UTC, [GitHub workflow 39746762688](https://github.com/rhamenator/request-guard-mcp/actions/runs/39746762688) built the unpublished `v1.0.0-rc.6` container candidate from draft PR #149 commit `553d53be2dcff9fb6030556766960184b6df0038`. The manual workflow ran separately on `ubuntu-24.04` amd64 and `ubuntu-24.04-arm` arm64 runners. Both jobs passed. It loaded private images into the runners; it did not push an image, create a release, or tag the repository. PR #149 remains draft and unmerged.

Each runner checked its native architecture, built `docker/Dockerfile` without cache, and ran the existing authenticated HTTP, custom WebSocket, and classifier client matrix against the local image. Both native client matrices passed. The probe then ran a two-slot container with a 512 MiB memory limit, 2 CPU limit, 128 PID limit, 4,096-byte request cap, and 10-second header timeout. Across 12 cycles of 32 attempts over roughly 63 seconds, each architecture shed 384/384 slow-header attempts and recovered authenticated service 12/12 times. The probe also required its sampled peak RSS to rise by less than 16 MiB. A final container inspection found it running with no OOM kill or restart. The nonempty server log was capped at 64 KiB and searched for the literal synthetic bearer; no match was found.

| Native amd64 | Passed | 384/384 | 12/12 | 9,908 → 10,252 KiB |
| Native arm64 | Passed | 384/384 | 12/12 | 8,228 → 8,332 KiB |

These probes used one synthetic bearer and direct Docker bridge IP traffic from each runner, without a published port, proxy, or TLS. The saturation test covered slow headers, not slow bodies, WebSocket exhaustion, or concurrent legitimate traffic. The observations are scoped to ephemeral GitHub runners and this commit; they are not throughput or memory guarantees. The private image was not pushed, so this run does not qualify a final published digest or attestations. The Dockerfile still uses mutable base image tags and package resolution; [issue #165](https://github.com/rhamenator/request-guard-mcp/issues/165) tracks reproducible image inputs. The final v1 release gate also requires scanner counts, npm and skill packaging, complete adversarial review, and owner approval; [issue #125](https://github.com/rhamenator/request-guard-mcp/issues/125) remains open.
