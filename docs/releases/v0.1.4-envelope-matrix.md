On 2026-10-20 (America/Detroit), the Linux x64 executable from the
v0.1.4 npm bundle was run on isolated host loopback. Its SHA-256 was
`e1863970dc8fdc96bb861af667bf7bc3f52810b2319190f8f2c192b033ab0fd5`,
identical to the checksum-verified public Linux x64 archive executable in
[`v0.1.4-kali-ubuntu-adversarial.md`](v0.1.4-kali-ubuntu-adversarial.md).

The stdlib-only `scripts/adversarial_envelope_v014_probe.py` (SHA-256
`93dd79fb5c4970caab1edfba89a896079cfa747fa8d430bb7f29566e5d7d2940`)
sent 13 deterministic HTTP POST cases through the running packaged binary:
malformed JSON, an array input, wrong JSON-RPC version, null and fractional
request IDs, invalid params with known ID, valid integer and string IDs,
accepted and rejected notifications, accepted and rejected client responses,
and a final healthy ping. It checked HTTP status, JSON-RPC code and ID,
success result, or empty one-way response body as applicable. **13/13 passed.**

Reproduce with a fresh synthetic bearer of at least 32 characters and a
checksum-verified v0.1.4 binary on a private lab address. The server must be
configured for bearer authentication. Pipe the bearer via stdin:

```bash
cat PRIVATE_TOKEN_FILE | python3 scripts/adversarial_envelope_v014_probe.py \
  --url http://LAB_IP:8085
```

The probe accepts only numeric private or loopback HTTP endpoints, disables
environment proxies, and refuses redirects. The recorded run set
`HTTP_PROXY`, `HTTPS_PROXY`, and `ALL_PROXY` to an unreachable local proxy,
with `NO_PROXY` and `no_proxy` empty; the probe still passed 13/13. The run
used an isolated host network namespace and a synthetic token. It did not
test the custom WebSocket transport, streaming SSE, or every MCP client; those
limits remain in issue #59 and the compatibility matrix.
