# Unpublished rc.23 cross-VM and musl PostgreSQL TLS gate

On 2026-10-24 UTC (2026-10-23 in the host's Detroit timezone), Kali
`copperfin-kali-full` probed the exact unpublished
v1.0.0-rc.23 Linux x64 glibc archive on Ubuntu `copperfin-ubuntu26-deb`.
A separate disposable Alpine container tested PostgreSQL TLS trust with the
matching musl archive. This is bounded private-candidate evidence, not stable
release approval.

This was one run of each stage, with no timing-variance or flakiness
measurement. The terminal showed aggregate case results; raw guest stdout
was not retained in Git. The Redis record was an ephemeral blocklisted test IP with source
`redis_blocklist`. PostgreSQL cluster 18 was verified online after restart,
the disposable database was removed, and Redis was shut down. The core,
PostgreSQL-backed and Redis-backed MCP logs were 10,290, 1,961 and 1,835
bytes respectively, each below 64 KiB.
Exact-string searches found no synthetic bearer, HMAC key or seeded
indicator in those scoped MCP logs. Encoded/truncated forms and backend

removed. Both lab guests were verified off; the preexisting Copperfin

boot and 0.36 after the TLS container and shutdown; these point samples
do not characterize the full run.

## PostgreSQL TLS trust and limits

`scripts/smoke_alpine_postgres_tls.py` ran the exact extracted musl binary in
pinned Alpine 3.24.2 base image
`sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`.
It passed explicit trusted CA, untrusted CA rejection, hostname mismatch,
unmodified OS-store rejection and OS-store trust after installing a test CA
inside the disposable container. PostgreSQL and MCP used container loopback;
PostgreSQL used trust authentication. The probe checked bounded private MCP
logs and `serverInfo.version`; assertions are in
`scripts/alpine_postgres_tls.py`. Docker's default network permitted live
`apk` installation, whose package revisions were not recorded. The
container was removed and Docker had no running containers afterward; no
host or guest CA store changed.

Cross-VM checks exercised glibc; TLS trust exercised musl. The other three
native platforms were packaged but not exercised in this lab. This does not
prove production TLS termination, glibc or other-platform TLS parity,
remote failover, Redis TLS, distributed ingress fairness, scanner capture
counts, all-client compatibility or a 256-client deployment. In particular,
the 22-case WebSocket matrix did not exercise the new per-bearer slot cap;
that behavior has separate private glibc/musl evidence in
[PR #242](https://github.com/rhamenator/request-guard-mcp/pull/242) and the
draft PR #149 candidate comment linked above. No public v1 tag, release,
GHCR image, npm package or Agensi
ZIP was created. Complete adversarial LLM review, owner approval and
approved-tag public artifact verification remain in
[issue #125](https://github.com/rhamenator/request-guard-mcp/issues/125).
