# PostgreSQL TLS qualification for the v0.1.4 candidate

The SQLx trust-root change in PR #113 is exercised by
`scripts/smoke_alpine_postgres_tls.py` against the **extracted, checksum-verified**
Linux musl release archive. The fixture runs in the pinned Alpine 3.24.2 image
with PostgreSQL 18, Python, OpenSSL, and `ca-certificates`. It exposes no host
port. Test keys and certificates are generated only in the disposable
container's `/tmp` tmpfs.

The local preflight on 2026-10-20 used the musl artifact from
[private candidate run 39489452461](https://github.com/rhamenator/request-guard-mcp/actions/runs/39489452461),
named
`request-guard-mcp-v0.1.4-rc.3-linux-x64-musl.tar.gz`, SHA-256
`241dde493e551d6cb64bdb35885bd5d19246f0bfb57db6e3e09fc44768ea7d13`.
The archive sidecar verified before extraction. The exact local command was
`python3 scripts/smoke_alpine_postgres_tls.py --binary <extracted-musl-binary> --expected-version 0.1.4`;
it printed `PASS Alpine PostgreSQL TLS: explicit CA, untrusted CA, hostname, OS store, private logs`.
The probe passed these five
cases with the exact packaged binary:

| Case | Expected result | Local result |
| --- | --- | --- |
| `sslmode=verify-full` with explicit trusted `sslrootcert` | Server starts; MCP initialize, classify, replay work | Pass |
| Explicit untrusted `sslrootcert` | Configured server fails closed at startup | Pass |
| Trusted CA, wrong DNS name | Configured server fails closed at startup | Pass |
| Native OS store before lab CA installation | Configured server fails closed at startup | Pass |
| Native OS store after lab CA installation | Server starts; MCP initialize, classify, replay work | Pass |

The disposable test checks that MCP and PostgreSQL server logs are nonempty,
bounded to 64 KiB each, and contain neither the synthetic bearer token nor
cache-scope key. A rejected case must exit nonzero and its MCP log must identify
the expected certificate verification cause (`UnknownIssuer` or a name mismatch); a generic startup failure or the wrong TLS cause cannot pass. It shuts
down PostgreSQL and the server, and removes the container after the run. A
misconfigured **required** PostgreSQL backend prevents server startup; the
core `classify` tool is not available in that state. This is a fail-closed
startup behavior, not a claim of continued core availability.

The release workflow runs the same probe on the verified musl archive for each
private candidate and tag. A local pass alone does not prove the exact public
tagged asset; check the tag workflow and published checksums before release.
This probe covers `sslmode=verify-full` only; `verify-ca`, `require`, and `prefer`
are outside its claim.
