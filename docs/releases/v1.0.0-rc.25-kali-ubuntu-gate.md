# Unpublished rc.25 cross-VM and musl PostgreSQL TLS gate

On 2026-10-24 UTC, Kali `copperfin-kali-full` probed the unpublished
v1.0.0-rc.25 Linux x64 glibc archive on Ubuntu `copperfin-ubuntu26-deb`.
A separate disposable Alpine container tested PostgreSQL TLS trust with the
matching Linux x64 musl archive. The other three native platforms were
packaged but not exercised in this lab. This is bounded private-candidate
evidence, not stable release approval.

The table records one run of each stage on the second of two lab boots, with
no timing-variance or flakiness measurement. The bounded per-case Kali stdout
is retained in
[`v1.0.0-rc.25-core-probe.jsonl`](v1.0.0-rc.25-core-probe.jsonl) and
[`v1.0.0-rc.25-backend-probe.txt`](v1.0.0-rc.25-backend-probe.txt).
The first run also passed but retained only aggregate counts; the second
run added the guest binary hash and per-case transcripts. The Redis record
used a synthetic domain with source `request_guard_lab`. The PostgreSQL
cluster was verified online after restart, the disposable database was
dropped, and Redis was shut down. The core, PostgreSQL-backed and Redis-backed
MCP logs were 10,290, 1,961 and 1,835 bytes respectively, each below 64 KiB.
Exact-string searches found no synthetic bearer, HMAC key or seeded
indicator in those scoped logs. Encoded/truncated forms and backend logs
were not searched. Guest processes, copied files, tokens and logs were
removed with scoped process termination and deletion of each guest's
`/tmp/request-guard-rc25` directory. Both lab guests were shut down through
their VM scripts and verified off via libvirt; the preexisting Copperfin
Windows guest was left running and untouched. Host I/O PSI `full avg10`
was 0.00 at one pre-boot and one post-shutdown observation; these point
samples do not characterize the full run.

## PostgreSQL TLS trust and limits

`scripts/smoke_alpine_postgres_tls.py` ran the exact extracted musl binary in
pinned Alpine 3.24.2 base image
`sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`.
It passed explicit trusted CA, untrusted CA rejection, hostname mismatch,
unmodified OS-store rejection and OS-store trust after installing a test CA
inside the disposable container. PostgreSQL and MCP used container loopback;
PostgreSQL used trust authentication. The probe checked bounded private MCP
logs and `serverInfo.version`; assertions are in
`scripts/alpine_postgres_tls.py`. Docker's default network permitted live
`apk` installation, whose package revisions were not recorded. The test CA
was generated inside the disposable container by the probe script, and the
OS-store rejection case preceded the trust-after-install case. This tests
TLS trust paths, not PostgreSQL authentication; package resolution and CA
tool versions were not pinned. The
container was removed and Docker had no running containers afterward; no
host or guest CA store changed.

Cross-VM checks exercised glibc; TLS trust exercised musl. The other three
native platforms were packaged but not exercised in this lab. This does not
prove production TLS termination, glibc or other-platform TLS parity,
remote failover, Redis TLS, distributed ingress fairness, scanner capture
counts, all-client compatibility or a 256-client deployment. The 22-case
WebSocket matrix did not itself exercise the per-bearer slot cap; separate
exact-candidate packaged evidence is in draft PR #149. No public v1 tag,
release, GHCR image, npm package or Agensi ZIP was created. Complete
adversarial LLM review, owner approval and approved-tag public artifact
verification remain in [issue #125](https://github.com/rhamenator/request-guard-mcp/issues/125).
