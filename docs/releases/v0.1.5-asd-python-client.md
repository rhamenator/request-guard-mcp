# AI Scraping Defense Python client against public v0.1.5

On 2026-10-21, the Python AI Scraping Defense MCP adapter connected to the exact public Request Guard MCP v0.1.5 Linux x64 binary (SHA256 `2c68a15272619d9b2240303815f4dcf61bc283eac3d022deb3227ea17711e25f`). The client code under test was `rhamenator/ai-scraping-defense` commit `4061cd3` in [PR #1848](https://github.com/rhamenator/ai-scraping-defense/pull/1848). Its isolated test environment used `mcp==1.29.0`, `websockets==15.0.1`, and `httpx==0.28.1`.

The request contained only synthetic metadata: `ip=192.0.2.42`, `user_agent=GPTBot/1.0`, `path=/robots.txt`, and `method=GET`. The generic adapter's former bare `mcp://primary/classify` setting wrapped those fields under `input`, yielding `allow`, score `0.0`, with no signals. With the explicit `mcp://primary/classify?argument_key=&options_key=` setting, the same adapter returned `block`, score `0.9181818181818181`, with `ua_ai_bot` and `ua_non_browser` signals. The latter result passed in three client paths:

- `MCPAdapter.predict()` over process-local stdio;
- `get_model_adapter()` using the `MODEL_URI` environment variable over stdio;
- `MCPAdapter.predict()` over an authenticated loopback WebSocket connection to `/mcp`.

The WebSocket test launched the public binary with a temporary synthetic 32-character bearer, waited for the loopback listener, called the adapter, then terminated the process. It did not use a VM, external network endpoint, production request, or real credential. The focused client tests (`test_mcp_adapter.py` and `test_mcp_client.py`) passed 5/5. The full Python repository test collection was attempted in a minimal client environment and stopped on missing unrelated project dependencies; its normal CI remains the source for full-suite results.

The `argument_key` query support merged to the AI Scraping Defense main branch in PR #1848 after review and CI. Operators need an installation containing that change before using the new URI. Existing deployments must not adopt the bare URI as a safe Request Guard classifier mapping. A caller using the already-available `call_mcp_tool()` helper with top-level request fields received the expected `block` result over both stdio and authenticated loopback WebSocket. This record proves one synthetic classify call on two transports, not end-to-end behavior of every AI Scraping Defense service or a v1.0 stable candidate.
