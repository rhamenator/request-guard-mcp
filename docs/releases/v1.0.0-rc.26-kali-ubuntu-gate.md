## TLS and logs

The operator reports extracting the Linux x64 musl binary from the archive and
running the repository's
disposable pinned-Alpine PostgreSQL TLS probe: explicit trusted CA, unknown CA
rejection, hostname mismatch rejection, OS trust store before/after CA
installation, and private log check. This does not qualify a customer's TLS
deployment. Alpine package resolution was live and is not a bit-for-bit
reproducibility claim (#165).
The musl archive SHA256 was
`dc9391c64adc58e50f1ce538fe43c4300f1fcde164a3933368bc40db769f8458`;
it is listed in the native archive digest record. The host-side binary SHA256
was
`518120cf172d63610d721f4399f1e9a0cb04adde61fa7a15f06bc444102c27cf`.
The supplied observations do not contain an extraction transcript tying the
two hashes together.

The Ubuntu MCP log sizes for core/PostgreSQL/Redis listeners were
10,290/1,961/1,835 bytes. Bounded literal matching found no synthetic bearer,
HMAC key, or Redis indicator in those three logs. This is not a general log
privacy proof.

Both Kali and Ubuntu were observed shut off after the run. PostgreSQL was
observed online. The disposable database drop, Redis shutdown, guest-file
deletion and temporary credential removal commands returned success, but no
independent post-deletion directory listing was retained. Docker had no
running containers. The pre-existing Copperfin VFP9 Windows guest was left
untouched.
