# Public v0.1.4 WebSocket envelope and client check

On 2026-10-20 (America/Detroit), the Linux x64 executable from the v0.1.4
npm bundle was run on isolated host loopback. Its SHA-256 was
`e1863970dc8fdc96bb861af667bf7bc3f52810b2319190f8f2c192b033ab0fd5`,
identical to the executable extracted from the checksum-verified public
v0.1.4 Linux x64 archive. The final `scripts/adversarial_ws_probe.py` SHA-256
was `28d565be7c70fe653642af6a36384c3356785db2189118fa8410fffb7a0b6802`.

The bounded WebSocket probe passed **22/22** cases against that binary. It
checked missing/wrong bearer rejection, authenticated upgrade and initialize,
malformed JSON, wrong JSON-RPC version, scalar/non-object params, array and
empty-object input, null and fractional request IDs, valid integer/string
IDs, rejected notifications and client results, accepted one-way notification
and client response with no frame in a 0.5-second observation window followed
by a successful ping on each same socket,
`tools/list`, oversized frame and fragmented-message close code 1009, and
recovery after size errors. Error cases check code `-32600` or `-32700` and
the required error ID. The probe accepts only numeric private or loopback lab
IP addresses and a valid port; its synthetic bearer is read from stdin.

The full `scripts/ci_adversarial_smoke.py` suite passed against the same
packaged executable, including the 13-case HTTP envelope matrix. Separately,
the pinned official MCP Inspector 2.5.0 was freshly installed and passed
missing-token rejection, `initialize` at `2025-06-18`, 23-tool listing,
`classify`, and `explain` with `--expected-version 0.1.4` against this exact
binary. This is the supported HTTP client path; WebSocket is a documented
custom transport exercised by the raw-frame probe.

To reproduce the WebSocket subset against an authorized lab listener, use a
new synthetic bearer token of at least 32 characters and set the server's
request limit to 4,096 bytes:

```bash
cat PRIVATE_TOKEN_FILE | python3 scripts/adversarial_ws_probe.py \
  --host LAB_PRIVATE_IP --port 8085 --max-request-bytes 4096
```

This run does not prove interoperability with every WebSocket client. The
server returns JSON for HTTP POST and 405 for an authenticated ordinary GET
`/mcp`; the [pinned 2025-06-18 transport specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)
permits both behaviors when no standalone SSE stream is offered. Optional SSE,
stdio, sessions/resumption, and a broader client matrix are tracked in issue
#121 and are not advertised as implemented.
