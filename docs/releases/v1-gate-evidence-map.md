# v1.0 release gate evidence map

This is a review map for [issue #125](https://github.com/rhamenator/request-guard-mcp/issues/125), not a stable-release approval. Evidence from v0.1.5 qualifies that **immutable experimental release** only. A v1.0 candidate must be built and the applicable probes repeated against its exact binaries and image digests. Request Guard classifies inbound requests; it does not intercept traffic sent through other agent tools.

| Gate | Existing v0.1.5 evidence | Required v1.0 candidate evidence |
| --- | --- | --- |
| Native package and clients | [Public archives, checksums, Inspector, SDK and stdio](v0.1.5-public-qualification.md); [Claude Code](v0.1.5-claude-code-stdio.md); [Cursor Agent CLI](v0.1.5-cursor-cli-stdio.md); [AI Scraping Defense Python adapter](v0.1.5-asd-python-client.md) | Record exact candidate tag and archive hashes, clean installation on every supported platform, then repeat the advertised client flows. Record actual versions and limits. |
| HTTP, WebSocket, malformed input and classifier evasion | [Kali-to-Ubuntu probes and scanner counts](v0.1.5-kali-ubuntu-adversarial.md) | Repeat the full bounded suite against the candidate, including authentication, Origin, oversized and malformed frames, classifier variants, synthetic-secret logs, failure recovery, on-wire scanner counts and resource measurements. |
| Backend failure and TLS | [PostgreSQL outage/recovery](v0.1.5-kali-ubuntu-postgres-recovery.md), [Redis outage/recovery](v0.1.5-kali-ubuntu-redis-recovery.md), [PostgreSQL TLS trust/rejection](v0.1.5-public-postgres-tls.md) | Repeat with candidate binaries and documented backend configuration; retain trusted/untrusted CA, hostname mismatch, outage and recovery results. |
| Container | [Published amd64 resource and adversarial probes](v0.1.5-public-ghcr-adversarial.md); the same record links the later native-runner amd64/arm64 51-case published-index probe | Verify the candidate's immutable multiarch index, each platform digest and provenance. Repeat native amd64 and arm64 client suites; repeat bounded resource and log probes on the release configuration. Do not infer arm64 resource coverage from the 51-case smoke. |
| npm and skill | [Public artifact qualification](v0.1.5-public-qualification.md) and the local-only v0.1.5 skill ZIP | Install the candidate npm package from a fresh registry cache, inspect its bundled archive hashes and run MCP client smoke. Inspect a clean ZIP containing only the matching `request-guard-mcp/SKILL.md`; verify every claim against the candidate. Keep the ZIP local until the owner decides to update Agensi. |
| Independent review and approval | Individual PR reviews and CI are linked from the evidence above | Reconcile independent reviews of the **complete candidate gate**, record unresolved limits, pass exact-head and tag CI/security checks, and obtain owner approval before stable publication. A review service outage is a documented gap, not a passing review. |

For the required probe scope and safety limits, use the [adversarial release gate](../adversarial-release-gate.md). Put candidate commands, hashes, tool versions, counts, host observations, findings and fixes in a new versioned evidence record. Update this map and issue #125 with links to that record before requesting owner review.
