The glibc binary was extracted from the verified Linux x64 archive; its SHA256 was `bd7e7ec539873aa36c5d1fb378af0eec5c2341cb8c77d24ea88f2e86ab9a7436`. On that host, the scripts started it on `127.0.0.1` with randomly generated synthetic bearer credentials. They unset backend URLs and used a temporary working directory. The HTTP suite configured 1-second header/body timeouts and a bounded request size; its burst server used a two-connection cap. The sustained probe used a two-connection cap and 10-second header timeout. The expected result was correct authentication/error/classifier outcomes, synthetic tokens absent from bounded logs, closed excess connections, and authenticated ping recovery after load. Commands:

```bash
python3 scripts/ci_adversarial_smoke.py --binary /path/to/extracted/request-guard-mcp
python3 scripts/adversarial_sustained_exhaustion_probe.py --binary /path/to/extracted/request-guard-mcp
```

The first command passed 10/10 HTTP, 22/22 custom WebSocket, 19/19 classifier, 128/128 seeded malformed envelopes, 13/13 HTTP envelope, 2/2 Redis-not-configured, 4/4 slow-client/body-limit, 3/3 synthetic-secret logging, and 3/3 connection-cap checks. Its 128-attempt burst shed 128/128 attempts and recovered by authenticated ping. The second command ran 63.39 seconds; with two held slow-header connections it shed 384/384 further attempts over 12 cycles and received a successful authenticated ping after every cycle. RSS rose from 11,292 to 11,704 KiB (412 KiB), below the script's 16 MiB growth limit. Its observed maximum shed latency was 8.85 ms, below the 2-second limit; sampled I/O PSI `some avg10` stayed `0.00`, with host one-minute load between 1.35 and 1.68. These are bounded observations on one host, not throughput or memory guarantees.

Only the Linux glibc archive's extracted binary was executed in this host run; the other four archives were checked against sidecars but not run. Sidecars from the same workflow detect corruption but are not independent provenance or signatures. The checks did not use Kali/Ubuntu VMs, healthy PostgreSQL/Redis backends, TLS trust, public GHCR or npm, or client installation on Windows/macOS.
